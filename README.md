# Локальный сборщик и анализатор чисел

Проект запускается локально командой:

```bash
python main.py
```

For VPS/autostart without the menu, run:

```bash
python main.py collect
```

Other direct modes:

```bash
python main.py analyze
python main.py diagnose
```

Он умеет:

- собирать числа с веб-страницы в `numbers.txt`;
- анализировать числа из `numbers.txt`;
- анализировать последовательность, которую вы вставили вручную.

## Установка

Откройте папку проекта в VS Code, затем в терминале выполните:

```bash
pip install -r requirements.txt
```

После установки Playwright нужно отдельно скачать браузер:

```bash
playwright install
```

## Настройки

Все основные настройки находятся в `config.py`.

```python
URL = "https://example.com"
NUMBER_SELECTOR = ""
FRAME_SELECTOR = ""
SCAN_ALL_FRAMES = True
READ_FROM_BODY_TEXT = True
HISTORY_BAR_ONLY = True
HISTORY_BAR_MAX_Y = 140
MIN_HISTORY_VALUE = 1.0
CLICK_TEXTS_BEFORE_START = []
WAIT_AFTER_CLICK = 2
CHECK_INTERVAL = 5
REFRESH_PAGE = False
SAVE_INITIAL_HISTORY = False
OUTPUT_FILE = "numbers.txt"
STATE_FILE = "state.json"
DEBUG_OUTPUT_FILE = "debug_page.txt"
```

`URL` - адрес страницы, с которой нужно собирать числа.

`NUMBER_SELECTOR` - CSS-селектор элементов, где находятся числа.

`FRAME_SELECTOR` - CSS-селектор iframe, если числа находятся внутри iframe. Если iframe не нужен, оставьте пустую строку.

`SCAN_ALL_FRAMES = True` означает, что программа пройдет по основной странице и всем iframe. Это удобно, если числа находятся внутри фрейма, но вы не знаете его селектор.

`READ_FROM_BODY_TEXT = False` означает, что программа читает только элементы по `NUMBER_SELECTOR`.

`READ_FROM_BODY_TEXT = True` означает, что программа берет весь видимый текст страницы и ищет числа в нем. Это помогает, если числа есть в тексте страницы, но сложно найти отдельный элемент.

`HISTORY_BAR_ONLY = True` означает, что программа ищет только видимые коэффициенты вида `1.27x` в верхнем баре, а похожие числа ниже на странице не берет.

`HISTORY_BAR_MAX_Y = 140` - нижняя граница верхнего бара по высоте экрана. Если нужный бар находится ниже, увеличьте это число.

`MIN_HISTORY_VALUE = 1.0` отсекает служебные значения вроде `0.00x`.

`CLICK_TEXTS_BEFORE_START` - список текстов, по которым нужно нажать перед началом сбора. Можно указывать полное название или часть текста.

Например:

```python
CLICK_TEXTS_BEFORE_START = ["Демо"]
```

Если нужно несколько кликов подряд:

```python
CLICK_TEXTS_BEFORE_START = ["Демо", "История"]
```

`WAIT_AFTER_CLICK` - сколько секунд ждать после каждого клика.

`CHECK_INTERVAL` - пауза между проверками страницы в секундах.

`REFRESH_PAGE = False` означает, что программа не обновляет страницу, а повторно читает уже открытый DOM.

`REFRESH_PAGE = True` означает, что перед каждой проверкой страница будет обновляться.

`SAVE_INITIAL_HISTORY = False` означает, что числа, которые уже были на странице при запуске, считаются старой историей и не записываются в `numbers.txt`.

`SAVE_INITIAL_HISTORY = True` означает, что начальная история тоже будет записана в `numbers.txt`.

## Как найти CSS-селектор

1. Откройте страницу в браузере.
2. Нажмите правой кнопкой на нужное число.
3. Выберите `Inspect` или `Просмотреть код`.
4. Найдите элемент, внутри которого лежит число.
5. Подберите простой селектор: класс `.price`, атрибут `[data-id]`, блок `.item .value`.
6. Вставьте его в `NUMBER_SELECTOR` в `config.py`.

Не указывайте слишком общий селектор вроде `body`, иначе программа может собрать лишние числа.

## Если числа не собираются

Запустите:

```bash
python main.py
```

Выберите:

```text
4
```

Программа создаст файл `debug_page.txt`. В нем будет видно:

- сколько элементов найдено по `NUMBER_SELECTOR`;
- сколько чисел найдено по текущим настройкам;
- есть ли числа в видимом тексте страницы;
- есть ли iframe;
- есть ли canvas.

Если в диагностике написано, что числа есть в тексте страницы, но текущий селектор их не находит, попробуйте временно поставить:

```python
READ_FROM_BODY_TEXT = True
```

Если числа внутри iframe, нужно указать два селектора:

```python
FRAME_SELECTOR = "iframe"
NUMBER_SELECTOR = ".number"
```

`FRAME_SELECTOR` выбирает сам iframe, а `NUMBER_SELECTOR` выбирает число уже внутри iframe.

Если селектор числа найти сложно, можно использовать более простой режим:

```python
NUMBER_SELECTOR = ""
FRAME_SELECTOR = ""
SCAN_ALL_FRAMES = True
READ_FROM_BODY_TEXT = True
HISTORY_BAR_ONLY = True
HISTORY_BAR_MAX_Y = 140
MIN_HISTORY_VALUE = 1.0
CLICK_TEXTS_BEFORE_START = ["Демо"]
```

Тогда программа нажмет на текст `Демо`, пройдет по странице и всем iframe, возьмет видимый текст и вытащит из него числа вроде `1.27x`, `3.46x`, `2.53x`.

Если на странице есть другие похожие коэффициенты не в истории, оставьте `HISTORY_BAR_ONLY = True`. Тогда сбор идет только с верхней полосы истории.

Если диагностика показывает `Canvas на странице`, а чисел в тексте нет, значит числа могут быть нарисованы как картинка. CSS-селектор такие числа не увидит, потому что в HTML нет отдельного текста с этим значением.

## Сбор чисел

Запустите:

```bash
python main.py
```

Выберите:

```text
1
```

Программа откроет страницу через Playwright и будет проверять элементы по селектору.

Новые записи сохраняются в формате:

```text
1 | 2.20
2 | 5.31
3 | 2.20
```

Одинаковые числа могут быть разными событиями. Поэтому программа сравнивает старую и новую последовательность как список, а не как набор уникальных значений.

Например:

```text
старое: 2.20, 8.40, 15.70
новое:  2.20, 2.20, 8.40, 15.70
```

Новым событием будет `2.20`.

Состояние хранится в `state.json`, чтобы после перезапуска не создавать очевидные дубликаты.

Если страница показывает CAPTCHA, Cloudflare challenge, HTTP 403, HTTP 429 или запрет доступа, программа остановится и не будет обходить защиту.

## Анализ из numbers.txt

Запустите:

```bash
python main.py
```

Выберите:

```text
2
```

Анализатор возьмет только числа после символа `|`.

## Ручной ввод

Запустите:

```bash
python main.py
```

Выберите:

```text
3
```

Можно вставлять числа так:

```text
3, 7, 5, 9, 7, 11, 9, 13
```

Или через пробелы и переносы строк.

## Что ищет анализатор

Сначала он ищет простые точные правила:

- арифметическую прогрессию;
- геометрическую прогрессию;
- повторяющиеся значения;
- повторяющиеся циклы;
- повторяющиеся циклы разностей;
- полиномиальные закономерности через конечные разности.

Если точного правила нет, он пробует модели `LinearRegression`, `Ridge` и `RandomForestRegressor`. Модели сравниваются с простым baseline: следующее число равно предыдущему.

Если сложная модель не лучше baseline, программа честно пишет, что убедительной закономерности не найдено.

## Как читать прогноз

Анализатор не всегда выводит одно точное число. Если числа шумные или похожи на случайные, он показывает более честный прогноз.

Возможные варианты:

```text
Предполагаемое следующее значение:
15.23
```

Такой вывод появляется, когда найдено точное правило.

```text
Предполагаемое следующее значение:
примерно 15.23 ± 1.50
```

Это значит: главный ориентир `15.23`, но на истории похожий метод ошибался примерно на `1.50`.

```text
Предполагаемое следующее значение:
Грубый диапазон: 15.67-15.80, ориентир 15.73
```

Это значит: надежного точного паттерна нет, поэтому лучше смотреть на диапазон, а не на одно число.

Чем больше реальных чисел накопится в `numbers.txt`, тем полезнее будет проверка моделей. Но если последовательность действительно случайная, программа не должна притворяться, что умеет точно угадывать. В таком случае она покажет низкую уверенность и грубый диапазон.

## Live prediction while collecting

When `PREDICT_AFTER_EACH_NEW_EVENT = True`, the collector updates
`prediction.txt` after every new number written to `numbers.txt`.

`numbers.txt` is append-only: the site may show only the latest 15-20 values,
but the local file keeps every collected value until you delete the file
yourself.

The prediction now has two layers:

- the numeric forecast from the existing analyzer;
- the bucket forecast for the next value: `<2`, `2-10`, or `10+`.

The bucket forecast looks for repeated transitions in history. For example,
if earlier data often had `10+ -> <2 -> <2 -> 2-10`, then after seeing the
same last buckets again it will mark `2-10` as the likely next bucket.
